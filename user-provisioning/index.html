User Provisioning Wizard

live

Create Microsoft 365 / Entra ID users, assign licenses, and add group memberships — for both Domestic (US) and Global / India onboarding, from one interface. Domestic users are also invited as B2B guests into a separate external tenant.

Download the tool (.zip)
Getting started

This is a desktop tool

Unlike the browser-based tools on the hub, this one runs locally because it creates users with admin permissions through PowerShell. Download the ZIP, unzip it, and launch it from the folder.

  1. Download and unzip the package. Keep all files together in one folder.
  2. Double-click Launch-UserProvisioningWizard.bat.
  3. First run on a machine: Windows SmartScreen may prompt — click More info → Run anyway.
  4. Sign in to Microsoft Graph and Exchange Online when prompted.
Always launch with the .bat, never the .ps1 directly. Running the .ps1 on its own can start PowerShell in the wrong mode and cause a "single-threaded apartment" error at the Exchange sign-in. The .bat avoids this.

Prerequisites

  • Windows PowerShell 5.1 (built in) or PowerShell 7.
  • Modules: Microsoft.Graph and ExchangeOnlineManagement.
  • An account with rights to create users and assign licenses (Graph User.ReadWrite.All, Group.ReadWrite.All, plus Exchange admin).
  • For Domestic batches only: a second sign-in to the external tenant, with rights there to invite guests and edit profiles (Guest Inviter or User Administrator). See "External tenant invites" below.

External tenant invites (Domestic mode only)

After a Domestic batch finishes creating users in the home tenant, each new user is also invited as a B2B guest into a separate external tenant — same UPN, no invite email sent, first/last name and job title copied over, no groups or roles assigned there.

  • Global/India batches are not affected — this only runs for Domestic.
  • The tool signs in a second time, to the external tenant, partway through the run, then reconnects to the home tenant automatically once done.
  • Whoever signs in at that prompt needs rights in the external tenant to invite guests and edit profiles (Guest Inviter or User Administrator).
  • The first time this runs in that tenant, a one-time consent screen may appear for the User.Invite.All and User.ReadWrite.All permissions — an admin there needs to accept it (or check "Consent on behalf of your organization" if offered) so future runs don't prompt again.
  • If the external sign-in or an invite fails, the home-tenant account is still created — the failure is only noted in Status and the results CSV.

Safety behavior

  • Existing users are never modified — skipped and flagged (enabled or disabled) so they can be handled manually.
  • Invalid rows are skipped individually; the rest of the batch still runs.
  • A missing group or failed license doesn't fail the user; the account is still created and the issue is noted.
  • Unique per-user passwords are generated (or a shared one), forced to change at first sign-in.
  • A results CSV with per-user status and password is written after each run — treat it as sensitive.
